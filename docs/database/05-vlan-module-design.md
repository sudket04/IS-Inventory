## 3. ตาราง `vlans` — ฟิลด์สำคัญ

### 3.1 กลุ่ม Subnet

| ฟิลด์ | ตัวอย่าง | กติกาที่ฐานข้อมูลบังคับ |
|---|---|---|
| `vlan_number` | `20` | ต้องอยู่ในช่วง **1–4094** ตามมาตรฐาน 802.1Q |
| `network_address` | `10.10.20.0` | ✅ ต้องเป็นรูปแบบ IPv4 ที่ถูกต้อง · ✅ **ต้องเป็นเลขที่อยู่เครือข่ายจริง** |
| `prefix_length` | `24` | ต้องอยู่ในช่วง 8–32 |
| `network_numeric` | `168432640` | คอลัมน์คำนวณอัตโนมัติ ใช้เปรียบเทียบช่วงและทำ Index |

> **กติกาที่ป้องกันความผิดพลาดได้มากที่สุด:** `CK_vlans_network_boundary`
> การกรอก `10.10.20.5/24` จะถูกปฏิเสธทันที เพราะเลขที่อยู่เครือข่ายที่ถูกต้องคือ `10.10.20.0/24`
> — นี่เป็นความผิดพลาดที่พบบ่อยที่สุดเวลากรอกข้อมูล Subnet ด้วยมือ และหากปล่อยผ่าน
> การคำนวณ IP ทั้ง VLAN จะผิดทั้งหมดโดยไม่มีใครรู้ตัว

### 3.2 กลุ่ม Gateway — "Gateway อยู่ที่อุปกรณ์ตัวไหน"

| ฟิลด์ | ค่าที่เป็นไปได้ | หมายเหตุ |
|---|---|---|
| `gateway_ip` | `10.10.20.1` | ✅ บังคับรูปแบบ IP · ✅ **ต้องอยู่ภายใน Subnet ของ VLAN นี้** |
| `gateway_device_role` | `FIREWALL` · `CORE_SWITCH` · `L3_SWITCH` · `ROUTER` · `OTHER` | ชนิดของอุปกรณ์ที่ทำหน้าที่ Gateway |
| `gateway_asset_id` | 🔗 ชี้ไปยัง `assets` | **ผูกกับอุปกรณ์จริงในระบบ** ทำให้คลิกดูได้ว่าเป็นเครื่องไหน อยู่ Rack ไหน หมดประกันเมื่อไร |
| `gateway_interface` | `Vlan20` · `port3` · `Gi1/0/1` | ชื่ออินเทอร์เฟซบนอุปกรณ์นั้น |

> **เหตุผลที่แยก `gateway_device_role` ออกจาก `gateway_asset_id`:** ระหว่างช่วงเริ่มกรอกข้อมูล
> ผู้ใช้อาจรู้ว่า "Gateway อยู่ที่ Firewall" แต่ยังไม่ได้บันทึก Firewall ตัวนั้นเข้าระบบ
> การแยกสองฟิลด์ทำให้กรอกข้อมูลที่รู้ก่อนได้ แล้วค่อยมาผูกกับอุปกรณ์จริงทีหลัง
> โดยระบบจะแสดงคำเตือน `GATEWAY_DEVICE_UNLINKED` เตือนให้ผูกให้ครบ

### 3.3 กลุ่มการจ่าย IP — "เป็น DHCP และมาจากอะไร"

| `ip_assignment_mode` | ความหมาย | ต้องระบุ `dhcp_source_type` |
|---|---|:---:|
| `STATIC_ONLY` | กำหนด IP ด้วยมือทั้งหมด | ❌ ห้ามระบุ |
| `DHCP_ONLY` | แจก IP อัตโนมัติทั้งหมด | ✅ บังคับ |
| `MIXED` | **มีทั้ง Static และ DHCP ใน VLAN เดียวกัน** | ✅ บังคับ |

**ค่าที่เป็นไปได้ของ `dhcp_source_type`**

| ค่า | ความหมาย |
|---|---|
| `FIREWALL` | Firewall ทำหน้าที่จ่าย DHCP |
| `CORE_SWITCH` | Core Switch จ่าย DHCP |
| `L3_SWITCH` | Layer 3 Switch จ่าย DHCP |
| `ROUTER` | Router จ่าย DHCP |
| `DHCP_SERVER` | เซิร์ฟเวอร์เฉพาะทาง เช่น Windows DHCP Server |
| `EXTERNAL` | ระบบภายนอกที่ไม่ได้บันทึกในระบบนี้ |

**กติกาที่ฐานข้อมูลบังคับ** (`CK_vlans_dhcp_consistency`)

```
ถ้า mode = STATIC_ONLY  →  dhcp_source_type, dhcp_server_asset_id, dhcp_relay_ip ต้องว่างทั้งหมด
ถ้า mode = DHCP_ONLY หรือ MIXED  →  dhcp_source_type ต้องมีค่าเสมอ
```

> **ทำไมต้องบังคับที่ระดับฐานข้อมูล ไม่ปล่อยให้แอปตรวจอย่างเดียว:** ข้อมูลที่ขัดแย้งกันเอง
> เช่น "VLAN นี้เป็น Static เท่านั้น แต่มี DHCP Server = Firewall ค้างอยู่" จะทำให้ทีม IT
> ไล่แก้ปัญหาผิดทางเป็นชั่วโมง — ฐานข้อมูลควรทำให้สถานะที่เป็นไปไม่ได้ **บันทึกไม่ได้ตั้งแต่แรก**

## 4. ตาราง `vlan_ip_ranges` — หัวใจของการคำนวณ IP

VLAN หนึ่งมีช่วง IP ได้ไม่จำกัดจำนวน แต่ละช่วงมี 4 ประเภท

| `range_type` | ความหมาย | นับรวมใน Pool ที่ใช้ได้ |
|---|---|:---:|
| `STATIC` | ช่วงสำหรับกำหนด IP ด้วยมือ | ✅ |
| `DHCP` | ช่วงที่ DHCP แจกอัตโนมัติ | ✅ |
| `RESERVED` | จองไว้สำหรับอุปกรณ์เครือข่าย (Gateway, HSRP/VRRP) | ✅ |
| `EXCLUDED` | กันไว้ ห้ามใช้ เช่น เตรียมขยายในอนาคต | ✅ |

**แต่ละช่วง DHCP ระบุแหล่งที่มาแยกได้** ผ่าน `dhcp_source_type` ระดับช่วง
รองรับกรณี VLAN เดียวมี DHCP มากกว่าหนึ่งแหล่ง (เช่น Firewall แจกช่วงหนึ่ง และ Windows DHCP แจกอีกช่วงหนึ่ง)

### 4.1 ตัวอย่างจริง — VLAN 20 แบบ MIXED

```
VLAN 20 · OA-USER-BKK · Zone: OA Network · 10.10.20.0/24 · Mode: MIXED
Gateway: 10.10.20.1 @ FIREWALL (NET-2024-0001 · Palo Alto PA-3220 · interface port3)
DHCP   : FIREWALL (NET-2024-0001)

┌──────────────────┬──────────┬──────────────────────────────────────────┐
│ ช่วง              │ ประเภท   │ คำอธิบาย                                  │
├──────────────────┼──────────┼──────────────────────────────────────────┤
│ .1    –    .10   │ RESERVED │ Gateway และอุปกรณ์เครือข่าย         10 IP │
│ .11   –    .99   │ STATIC   │ เครื่องพิมพ์ IP Phone อุปกรณ์ตายตัว  89 IP │
│ .100  –   .250   │ DHCP     │ เครื่องผู้ใช้ทั่วไป (จาก Firewall)  151 IP │
│ .251  –   .254   │    —     │ ยังไม่ได้จัดสรร                       4 IP │
└──────────────────┴──────────┴──────────────────────────────────────────┘
```

## 5. ตรรกะการคำนวณ IP (View `vw_vlan_summary`)

### 5.1 ค่าที่คำนวณจาก Subnet

| ค่า | สูตร | ตัวอย่าง `/24` |
|---|---|---|
| `total_addresses` | `2 ^ (32 − prefix)` | `256` |
| `usable_addresses` | `total − 2` (สำหรับ prefix ≤ 30) | `254` |
| `subnet_mask` | `4294967295 − (total − 1)` แปลงกลับเป็น IP | `255.255.255.0` |
| `broadcast_address` | `network + total − 1` | `10.10.20.255` |
| `first_usable_ip` | `network + 1` | `10.10.20.1` |
| `last_usable_ip` | `network + total − 2` | `10.10.20.254` |

> **กรณีพิเศษที่ระบบรองรับ:** `/31` มีที่อยู่ใช้ได้ 2 ค่า (ลิงก์จุดต่อจุดตาม RFC 3021)
> และ `/32` มี 1 ค่า — ระบบไม่หัก 2 ในสองกรณีนี้ ซึ่งเป็นจุดที่เครื่องคำนวณ Subnet
> ทั่วไปมักคำนวณผิดเป็นค่าติดลบ

### 5.2 ค่าที่คำนวณจาก Pool

| ค่า | ความหมาย |
|---|---|
| `static_pool_size` | รวมขนาดทุกช่วงประเภท `STATIC` |
| `dhcp_pool_size` | รวมขนาดทุกช่วงประเภท `DHCP` |
| `reserved_pool_size` · `excluded_pool_size` | รวมขนาดช่วงที่จองและกันไว้ |
| `unplanned_addresses` | `usable − static − dhcp − reserved − excluded` — **ที่อยู่ที่ยังไม่ได้วางแผนใช้งาน** |
| `pool_coverage_percent` | สัดส่วนที่วางแผนไว้แล้วเทียบกับที่ใช้ได้ทั้งหมด |

### 5.3 ค่าที่คำนวณจากการใช้งานจริง

| ค่า | ความหมาย | ที่มาของข้อมูล |
|---|---|---|
| `known_ips_in_subnet` | จำนวน IP ที่บันทึกไว้ในระบบและอยู่ใน Subnet นี้ | View `vw_all_ip_addresses` |
| `static_ips_used` | จำนวน IP ที่ใช้อยู่และตกอยู่ในช่วง `STATIC` | เทียบค่าตัวเลขของ IP กับขอบเขตช่วง |
| `static_ips_available` | `static_pool_size − static_ips_used` | ⭐ **ตัวเลขที่ทีม IT ถามบ่อยที่สุด** |
| `ips_outside_any_pool` | IP ที่ใช้อยู่แต่ไม่อยู่ในช่วงใดเลย | สัญญาณว่าแผนผัง IP ไม่ตรงกับความเป็นจริง |
| `static_utilization_percent` | อัตราการใช้ช่วง Static | ใช้เตือนก่อนช่วงเต็ม |

### 5.4 View `vw_all_ip_addresses` — รวม IP ทั้งระบบ

รวม IP จาก **4 แหล่ง** ที่กระจายอยู่ในตารางขยายต่างๆ ให้อยู่ในมุมมองเดียว

| แหล่ง | คอลัมน์ | `ip_purpose` |
|---|---|---|
| `server_details` | `ip_address` | `SERVICE` |
| `server_details` | `mgmt_ip` (iDRAC / iLO) | `MANAGEMENT` |
| `network_details` | `mgmt_ip` | `MANAGEMENT` |
| `computer_details` | `ip_address` | `SERVICE` |

> **จุดเด่นของการออกแบบนี้:** ไม่ต้องกรอกข้อมูล IP ซ้ำอีกรอบในโมดูล VLAN
> ระบบดึง IP ที่บันทึกไว้แล้วในทะเบียนอุปกรณ์มาคำนวณให้เอง โดยเทียบจากค่าตัวเลขของ IP
> ว่าตกอยู่ใน Subnet ใด — **ข้อมูลชุดเดียว ไม่มีทางไม่ตรงกัน**

### 5.5 ⚠️ ข้อจำกัดที่ต้องทราบ

| ข้อจำกัด | รายละเอียด |
|---|---|
| **ไม่ทราบจำนวน DHCP Lease ที่ใช้จริง** | ระบบรายงานได้แค่**ขนาดของช่วง DHCP** ไม่ใช่จำนวนเครื่องที่กำลังเช่า IP อยู่ เพราะไม่ได้เชื่อมต่อกับ DHCP Server (อยู่นอก Scope ตาม PRD §4.2) |
| **นับเฉพาะ IP ที่บันทึกในระบบ** | หากยังไม่ได้กรอก IP ของอุปกรณ์ ระบบจะไม่นับให้ — ตัวเลข `static_ips_used` จึงเป็น **"เท่าที่รู้"** ไม่ใช่ "ทั้งหมดที่มีจริง" |
| **ทางแก้ใน Phase 2** | เชื่อม DHCP Server ผ่าน API หรือทำ Network Scan (เป็นฟีเจอร์เดียวกับ Auto-Discovery ที่เลื่อนไว้) |

> ผมระบุข้อจำกัดนี้ไว้อย่างชัดเจน เพราะหน้าเว็บที่แสดงคำว่า "DHCP Available: 151"
> โดยไม่บอกว่าเป็นเพียงขนาดช่วง จะทำให้ผู้ใช้เข้าใจผิดว่าเหลือ 151 เครื่องจริง
> — **หน้าเว็บต้องใช้คำว่า "DHCP Pool Size" ไม่ใช่ "Available"**

## 6. View ตรวจสอบความผิดปกติ (`vw_vlan_validation_issues`)

| รหัส | ระดับ | ตรวจจับอะไร |
|---|:---:|---|
| `RANGE_OUTSIDE_SUBNET` | 🔴 Error | ช่วง IP ที่กำหนดอยู่นอก Subnet ของ VLAN |
| `RANGE_OVERLAP` | 🔴 Error | ช่วง IP สองช่วงใน VLAN เดียวกันซ้อนทับกัน |
| `UNEXPECTED_DHCP_POOL` | 🔴 Error | ระบุว่าเป็น Static เท่านั้น แต่มีช่วง DHCP อยู่ |
| `DHCP_POOL_MISSING` | 🟡 Warning | ระบุว่าใช้ DHCP แต่ยังไม่ได้กำหนดช่วง DHCP |
| `IP_OUTSIDE_POOL` | 🟡 Warning | มี IP ใช้งานอยู่แต่ไม่อยู่ในช่วงใดเลย |
| `GATEWAY_DEVICE_UNLINKED` | 🟡 Warning | มี Gateway IP แต่ยังไม่ผูกกับอุปกรณ์จริง |
| `DHCP_DEVICE_UNLINKED` | 🟡 Warning | ระบุแหล่ง DHCP เป็นอุปกรณ์ภายใน แต่ยังไม่ผูกกับอุปกรณ์จริง |

> ปัญหาเหล่านี้ฐานข้อมูลบังคับล่วงหน้าไม่ได้ทั้งหมด เพราะต้องเทียบข้ามแถวและข้ามตาราง
> แต่การมี View ตรวจให้ ทำให้หน้าเว็บแสดงคำเตือนได้ทันที **แทนที่จะให้ผู้ใช้ค้นพบเองตอนระบบล่ม**

## 7. การบังคับรูปแบบ IP ทั้งระบบ

### 7.1 ฟังก์ชันที่ใช้

| ฟังก์ชัน | ใช้กับ | ความเข้มงวด |
|---|---|---|
| `fn_is_valid_ipv4` | ทุกฟิลด์ในโมดูล VLAN | **เข้มงวด** — 4 ส่วน · แต่ละส่วน 0–255 · ไม่มีเลขนำหน้าศูนย์ · ไม่มีอักขระอื่น |
| `fn_is_valid_ip` | ฟิลด์ IP ของอุปกรณ์ (`server_details` ฯลฯ) | ยอมรับ IPv4 เข้มงวด **หรือ** รูปแบบ IPv6 เบื้องต้น |

### 7.2 ฟิลด์ที่ถูกบังคับ

| ตาราง | ฟิลด์ | Constraint |
|---|---|---|
| `vlans` | `network_address` | `CK_vlans_network_ip` |
| `vlans` | `gateway_ip` | `CK_vlans_gateway_ip` |
| `vlans` | `dhcp_relay_ip` | `CK_vlans_relay_ip` |
| `vlans` | `dns_primary` · `dns_secondary` | `CK_vlans_dns1_ip` · `CK_vlans_dns2_ip` |
| `vlan_ip_ranges` | `start_ip` · `end_ip` | `CK_ranges_start_ip` · `CK_ranges_end_ip` |
| `server_details` | `ip_address` · `mgmt_ip` | `CK_server_ip_format` · `CK_server_mgmt_ip_format` |
| `network_details` | `mgmt_ip` | `CK_network_mgmt_ip_format` |
| `computer_details` | `ip_address` | `CK_computer_ip_format` |

### 7.3 ตัวอย่างค่าที่ถูกปฏิเสธ

| ค่าที่กรอก | เหตุผลที่ถูกปฏิเสธ |
|---|---|
| `10.10.20` | มีไม่ครบ 4 ส่วน |
| `10.10.20.256` | ส่วนที่ 4 เกิน 255 |
| `10.10.20.01` | มีเลขนำหน้าศูนย์ (อาจถูกตีความเป็นเลขฐานแปดในบางระบบ) |
| `10.10.20.1 ` | มีช่องว่างต่อท้าย |
| `192.168.1.1/24` | มีอักขระที่ไม่ใช่ตัวเลขและจุด |
| `Vlan20` | ไม่ใช่รูปแบบ IP |

> **ข้อควรทราบสำหรับทีมพัฒนา:** แม้ฐานข้อมูลจะบังคับให้แล้ว ฝั่ง Frontend ยังต้องตรวจซ้ำอยู่ดี
> เพราะข้อความผิดพลาดจากฐานข้อมูลอ่านไม่รู้เรื่องสำหรับผู้ใช้ — ฐานข้อมูลเป็น**ด่านสุดท้าย**
> ไม่ใช่ด่านแรก แต่ต้องมี เพราะการนำเข้าข้อมูลจาก Excel อาจข้ามการตรวจของหน้าเว็บไปได้
