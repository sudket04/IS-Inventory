| `vendor_id` | `INT` | ⬜🔗 | ผู้ขายหรือผู้ให้บริการ MA | ใช้ในรายงานเพื่อการต่อสัญญา |
| `po_number` | `NVARCHAR(50)` | ⬜ | เลขที่ใบสั่งซื้อ | ใช้เชื่อมกับเอกสารจัดซื้อ |

| `coverage_end_date` | `DATE` | ⬜ | **ฮาร์ดแวร์:** วันหมดประกัน · **ซอฟต์แวร์:** วันหมด License | ต้อง `>= coverage_start_date` · ⭐ **คอลัมน์ที่งานแจ้งเตือนทั้งระบบสแกน** |

| `custom_attributes` | `NVARCHAR(MAX)` | ⬜ | คุณสมบัติเฉพาะของ Storage และ Peripheral | ต้องเป็น JSON ที่ถูกต้อง (บังคับด้วย `ISJSON`) |
| `last_verified_at` | `DATE` | ⬜ | วันที่ตรวจนับทรัพย์สินครั้งล่าสุด | ใช้ทำรายงาน "ข้อมูลที่ไม่ถูกแตะต้องนาน" — มาตรการรับมือความเสี่ยงข้อมูลเก่า (PRD §13.2) |
| `is_deleted` | `BIT` | ❗ | ธงการลบแบบ Soft Delete | ค่าเริ่มต้น `0` · **ทุก Query ของผู้ใช้ต้องกรอง `is_deleted = 0` เสมอ** |

### 1.1 กติกาสำคัญที่ฐานข้อมูลบังคับไม่ได้ (ต้องทำที่ Application Layer)

| # | กติกา | เหตุผลที่บังคับใน SQL ไม่ได้ |
|---|---|---|
| 1 | หากประเภทเป็น `SRV` ต้องมีแถวใน `server_details` | SQL Server ไม่รองรับ Subquery ใน `CHECK` Constraint |
| 2 | `software_asset_id` ต้องเป็นทรัพย์สินประเภท `SFT` | เหตุผลเดียวกัน |
| 3 | Serial ซ้ำต้องแจ้งพร้อม**ลิงก์ไปยังรายการเดิม** | ฐานข้อมูลแจ้งได้แค่ว่าซ้ำ แต่บอกไม่ได้ว่าซ้ำกับรายการไหน |
| 4 | ห้ามเปลี่ยน `category_id` หลังบันทึก | ต้องใช้ตรรกะเปรียบเทียบค่าเดิม ซึ่งทำที่แอปพลิเคชันชัดเจนกว่า |

> **เหตุผลที่เลือกทำที่ Application Layer:** ข้อความแจ้งเตือนจากฐานข้อมูลอ่านไม่รู้เรื่องสำหรับผู้ใช้ทั่วไป
> การตรวจที่แอปพลิเคชันทำให้แสดงข้อความที่บอกวิธีแก้ได้ ตามหลักที่กำหนดไว้ใน Design System §6.2

## 2. ตารางขยายเฉพาะทาง

### 2.1 `server_details`

| คอลัมน์ | ชนิดข้อมูล | ความหมาย | หมายเหตุ |
|---|---|---|---|
| `server_type` | `VARCHAR(10)` ❗ | `PHYSICAL` หรือ `VIRTUAL` | ถ้าเป็น `VIRTUAL` ควรระบุ `parent_host_asset_id` ด้วย |
| `hostname` | `NVARCHAR(100)` | ชื่อเครื่องในเครือข่าย | มี Index สำหรับค้นหา (FR-SE-01) |
| `ip_address` | `VARCHAR(45)` | IP สำหรับให้บริการ | รองรับ IPv6 · ตรวจรูปแบบที่ Application |
| `mgmt_ip` | `VARCHAR(45)` | IP ของ iDRAC / iLO / IPMI | แยกจาก IP ปกติ เพราะใช้คนละวัตถุประสงค์ |
| `mac_address` | `VARCHAR(17)` | รูปแบบ `00:1A:2B:3C:4D:5E` | แปลงเป็นตัวพิมพ์ใหญ่และใช้ `:` เป็นตัวคั่นเสมอ |
| `cpu_model` | `NVARCHAR(150)` | เช่น `Intel Xeon Gold 6338` | — |
| `cpu_socket_count` | `TINYINT` | จำนวน CPU ที่ติดตั้ง | 1–8 |
| `cpu_core_count` | `SMALLINT` | จำนวนคอร์รวม | ใช้คำนวณ License แบบ Core-based |
| `ram_gb` | `INT` | หน่วยความจำ (GB) | `> 0` |
| `storage_config` | `NVARCHAR(300)` | เช่น `4× 1.92TB SSD RAID 10` | เก็บเป็นข้อความอ่านง่าย ไม่แยกฟิลด์ เพราะรูปแบบหลากหลายเกินกว่าจะทำเป็นโครงสร้าง |
| `os_install_date` / `last_patch_date` | `DATE` | วันติดตั้ง / วันแพตช์ล่าสุด | ใช้ทำรายงานเครื่องที่ไม่ได้อัปเดตนาน |
| `parent_host_asset_id` | `INT` 🔗 | VM นี้อยู่บน Host เครื่องไหน | ห้ามชี้กลับมาที่ตัวเอง |

> และแทนที่ด้วยโมดูล VLAN/IPAM เต็มรูปแบบ ความสัมพันธ์ "อุปกรณ์นี้รองรับ VLAN ใดบ้าง"
> อยู่ในตาราง `vlan_devices` ดูรายละเอียดใน `05-vlan-module-design.md`

### 2.4 `software_details`

| คอลัมน์ | ความหมาย | หมายเหตุ |
|---|---|---|
| `publisher` | ผู้ผลิตซอฟต์แวร์ เช่น `Microsoft`, `VMware` | |
| `license_type` ❗ | `PERPETUAL` · `SUBSCRIPTION` · `OEM` · `VOLUME` · `CORE_BASED` · `OPEN_SOURCE` | มีผลต่อการตีความ `coverage_end_date` |
| `license_key_encrypted` | `VARBINARY(1024)` | 🔒 **เข้ารหัส AES-256-GCM ที่ Application** ไม่ใช่ที่ฐานข้อมูล · การกดเปิดดูต้องบันทึก Audit Log ด้วย `action = REVEAL_KEY` |
| `seats_purchased` ❗ | จำนวนสิทธิ์ที่ซื้อมา | `> 0` · ค่าตั้งต้น `1` |
| `is_per_device` | นับสิทธิ์ตามเครื่อง (`1`) หรือตามผู้ใช้ (`0`) | MVP รองรับแบบตามเครื่องเป็นหลัก |

> ระบบจะไม่นำไปคิดในการแจ้งเตือน และหน้าเว็บจะแสดงคำว่า `Perpetual` แทนวันที่

## 3. ตาราง `software_installations` — หัวใจของการนับ Seat

| คอลัมน์ | ความหมาย | กติกา |
|---|---|---|
| `software_asset_id` ❗🔗 | ทรัพย์สินประเภท Software | ตรวจประเภทที่ Application Layer |
| `target_asset_id` ❗🔗 | เครื่องที่ติดตั้ง | ห้ามเท่ากับ `software_asset_id` |
| `installed_date` | วันที่ติดตั้ง | |
| `removed_date` | วันที่ถอนการติดตั้ง | ⭐ **`NULL` = ยังใช้สิทธิ์อยู่ → เป็นตัวกำหนดการนับ Seat ทั้งหมด** |
| `is_active` | คอลัมน์คำนวณอัตโนมัติจาก `removed_date` | `PERSISTED` · ห้ามเขียนค่าโดยตรง |

### 3.1 ทำไมใช้ `removed_date` แทนการลบแถวทิ้ง

| เหตุผล | ผลที่ได้ |
|---|---|
| รักษาประวัติว่าเคยติดตั้งอะไรไว้ที่ไหน | ตอบคำถามผู้ตรวจสอบได้ว่า "ปีที่แล้วซอฟต์แวร์ตัวนี้อยู่บนเครื่องไหนบ้าง" |
| การถอนการติดตั้งเป็นเหตุการณ์ทางธุรกิจ | ต้องรู้ว่าใครถอน เมื่อไร (`removed_by`, `removed_date`) |
| Seat คืนกลับทันทีเมื่อกำหนด `removed_date` | ไม่ต้องเขียนตรรกะซับซ้อน — View นับเฉพาะแถวที่ `removed_date IS NULL` |

## 4. ตาราง `audit_logs` — หลักฐานการตรวจสอบ

| คอลัมน์ | ความหมาย | หมายเหตุสำคัญ |
|---|---|---|
| `occurred_at` ❗ | เวลาที่เกิดเหตุการณ์ | ใช้ `DATETIMEOFFSET` เก็บ Time Zone ด้วย — **จำเป็นต่อการเป็นหลักฐาน** |
| `user_id` ⬜🔗 | ผู้กระทำ | **อนุญาตให้ว่างได้** เพราะกรณี Login ล้มเหลวด้วยชื่อที่ไม่มีอยู่จริง จะไม่มี `user_id` ให้อ้างอิง |
| `username_snapshot` ⬜ | สำเนาชื่อผู้ใช้ ณ เวลานั้น | 🔒 เก็บไว้เพราะหากบัญชีถูกเปลี่ยนชื่อหรือระงับภายหลัง หลักฐานต้องยังแสดงชื่อเดิมได้ |
| `action` ❗ | ประเภทการกระทำ 16 ค่า | บังคับด้วย `CHECK` Constraint |
| `entity_type` / `entity_id` | ตารางและรหัสที่ถูกกระทำ | ใช้กรองประวัติของทรัพย์สินรายการเดียว |
| `entity_label` | ป้ายชื่อที่มนุษย์อ่านได้ เช่น `SRV-2026-0031` | เก็บไว้เพื่อให้รายงานอ่านได้แม้รายการต้นทางถูกลบ |
| `before_json` / `after_json` | ค่าก่อนและหลังเปลี่ยน | ต้องเป็น JSON ที่ถูกต้อง · 🔒 **ห้ามบันทึกรหัสผ่านหรือ License Key ลงไป** |
| `changed_fields` | รายชื่อฟิลด์ที่เปลี่ยน คั่นด้วยจุลภาค | ช่วยให้กรองได้เร็วโดยไม่ต้องแกะ JSON |
| `ip_address` / `user_agent` | ที่มาของคำขอ | จำเป็นต่อการสืบสวนเหตุผิดปกติ |
| `batch_uid` | รหัสชุดการนำเข้าข้อมูล | ทำให้การ Import 1,879 รายการบันทึกเป็น Audit Log **1 รายการ** แทนที่จะเป็น 1,879 รายการ |

### 4.1 ค่าที่เป็นไปได้ของ `action`

| กลุ่ม | ค่า |
|---|---|
| ข้อมูลทรัพย์สิน | `CREATE` · `UPDATE` · `DELETE` · `RESTORE` |
| การเข้าใช้งาน | `LOGIN` · `LOGOUT` · `LOGIN_FAILED` · `USER_LOCKED` |
| การจัดการข้อมูล | `IMPORT` · `EXPORT` · `FILE_UPLOAD` · `FILE_DELETE` |
| ความปลอดภัย | `REVEAL_KEY` · `PASSWORD_CHANGE` · `PASSWORD_RESET` · `SETTING_CHANGE` |

> **ข้อควรระวังในการพัฒนา:** ก่อนบันทึก `before_json` และ `after_json` ต้องกรองฟิลด์ที่เป็นความลับออกก่อนเสมอ
> (`password_hash`, `license_key_encrypted`, `smtp.password`) มิฉะนั้น Audit Log ที่ควรเป็นหลักฐาน
> จะกลายเป็นแหล่งรั่วไหลของข้อมูลลับเสียเอง

## 5. ตาราง `notification_history` — กลไกกันส่งซ้ำ

| คอลัมน์ | ความหมาย |
|---|---|
| `threshold_days` ❗ | เกณฑ์ที่ทำให้เกิดการแจ้งเตือน: `90` `60` `30` `7` |
| `coverage_end_snapshot` ❗ | ⭐ **สำเนาวันหมดอายุ ณ เวลาที่ส่ง** — กุญแจสำคัญของกลไกทั้งหมด |
| `channel` ❗ | `EMAIL` หรือ `IN_APP` |
| `status` ❗ | `SENT` หรือ `FAILED` |

**ตัวอย่างการทำงานจริง**

| เหตุการณ์ | ผลลัพธ์ |
|---|---|
| วันที่ 1 — ส่งแจ้งเตือน 90 วันของ `SFT-2024-0005` (หมดอายุ 30 Nov 26) | บันทึก `(asset=5, 90, '2026-11-30', EMAIL)` |
| วันที่ 2 — Job ทำงานอีกครั้ง เงื่อนไขยังตรง | Unique Index ปฏิเสธการบันทึกซ้ำ → **ไม่ส่งอีเมล** ✅ |
| วันที่ 10 — ผู้ใช้ต่อสัญญา แก้วันหมดอายุเป็น 30 Nov 27 | ค่า Snapshot ใหม่ต่างจากเดิม → เริ่มนับรอบแจ้งเตือนใหม่อัตโนมัติ ✅ |

> Unique Index ตั้งเงื่อนไข `WHERE status = 'SENT'` โดยเจตนา — การส่งที่**ล้มเหลว**ต้องลองใหม่ได้
> มิฉะนั้นอีเมลที่ส่งไม่สำเร็จเพราะ SMTP ล่มชั่วคราวจะไม่มีวันถูกส่งอีกเลย

## 6. ตาราง `users` — ฟิลด์ที่เกี่ยวกับความปลอดภัย

| คอลัมน์ | ความหมาย | กติกา |
|---|---|---|
| `password_hash` ❗ | ค่า Hash แบบ Argon2id | 🔒 **ห้ามเก็บรหัสผ่านดิบหรือ Hash แบบ MD5/SHA1 โดยเด็ดขาด** · ห้ามส่งออกทาง API ทุกกรณี |
| `failed_login_attempts` ❗ | ตัวนับความผิดพลาดสะสม | รีเซ็ตเป็น `0` เมื่อ Login สำเร็จ |
| `locked_until` ⬜ | ล็อกบัญชีถึงเวลาใด | `NULL` = ไม่ถูกล็อก · ตั้งเป็นเวลาปัจจุบัน + 15 นาที เมื่อผิดครบ 5 ครั้ง |
| `must_change_password` ❗ | บังคับเปลี่ยนรหัสผ่านตอนเข้าครั้งแรก | ตั้งเป็น `1` เมื่อ Admin สร้างบัญชีใหม่หรือรีเซ็ตรหัสผ่านให้ |
| `is_active` ❗ | สถานะการใช้งานบัญชี | ⭐ **การระงับสิทธิ์ใช้การตั้งค่านี้เป็น `0` ไม่ใช่การลบแถว** (FR-AU-09) เพื่อรักษาความสมบูรณ์ของ Audit Log |
| `external_id` ⬜ | รหัสอ้างอิงจากระบบภายนอก | ว่างไว้ใน MVP · เตรียมรองรับ SSO ในอนาคตโดยไม่ต้องแก้โครงสร้าง |

## 7. สรุปชนิดข้อมูลที่ใช้และเหตุผล

| ชนิดข้อมูล | ใช้กับ | เหตุผล |
|---|---|---|
| `INT IDENTITY` | Primary Key ของตารางทั่วไป | รองรับได้ 2.1 พันล้านแถว · Index เล็กและเร็วกว่า `UNIQUEIDENTIFIER` มาก |
| `BIGINT IDENTITY` | `audit_logs` · `notifications` · `refresh_tokens` | ตารางที่เติบโตเร็ว ป้องกันการเต็มในระยะยาว |
| `NVARCHAR` | ทุกฟิลด์ข้อความที่ผู้ใช้กรอก | รองรับภาษาไทยในช่อง Notes และชื่อบุคคล แม้หน้าเว็บจะเป็นภาษาอังกฤษ |
| `VARCHAR` | รหัสระบบ · IP · MAC · Hash | ข้อมูลเหล่านี้เป็น ASCII เสมอ ใช้ `VARCHAR` ประหยัดพื้นที่ครึ่งหนึ่ง |
| `DATE` | วันที่ซื้อ · วันหมดอายุ · วันติดตั้ง | ไม่ต้องการส่วนของเวลา และเปรียบเทียบได้ตรงไปตรงมากว่า |
| `DATETIMEOFFSET(3)` | Timestamp ทุกตัวในระบบ | ⭐ เก็บ Time Zone ไว้ด้วย — สำคัญมากสำหรับหลักฐานการตรวจสอบ · ความละเอียดระดับมิลลิวินาทีเพียงพอ |
| `DECIMAL(18,2)` | ราคาและจำนวนเงิน | 🔒 **ห้ามใช้ `FLOAT` หรือ `REAL` กับข้อมูลการเงินโดยเด็ดขาด** เพราะเกิดความคลาดเคลื่อนจากการปัดเศษ |
| `BIT` | ธงค่าจริง/เท็จ | ประหยัดพื้นที่ที่สุดใน SQL Server |
| `VARBINARY` | License Key ที่เข้ารหัสแล้ว | เก็บ Ciphertext แบบไบนารีโดยตรง ไม่ต้องแปลงเป็น Base64 ให้เปลืองพื้นที่ |
| `NVARCHAR(MAX)` + `ISJSON` | `custom_attributes` · `before_json` · `after_json` | ยืดหยุ่นโดยยังมีการตรวจความถูกต้องของรูปแบบ |
| `UNIQUEIDENTIFIER` | `batch_uid` | ต้องสร้างรหัสได้จากฝั่งแอปพลิเคชันก่อนบันทึกลงฐานข้อมูล |

## 8. กติกาการตรวจสอบข้อมูลที่ใช้ร่วมกันทั้งระบบ

| ประเภทข้อมูล | รูปแบบที่ยอมรับ | การจัดรูปแบบก่อนบันทึก |
|---|---|---|
| IP Address | IPv4 หรือ IPv6 ที่ถูกต้อง | ตัดช่องว่าง · ตรวจด้วย Regex ที่ Application |
| MAC Address | 6 ชุดคั่นด้วย `:` หรือ `-` | แปลงเป็น**ตัวพิมพ์ใหญ่และใช้ `:` เสมอ** เพื่อให้ค้นหาเจอ |
| Serial Number | ตัวอักษร ตัวเลข ขีดกลาง | ตัดช่องว่าง · เทียบแบบไม่สนตัวพิมพ์เล็กใหญ่ |
| Email | รูปแบบอีเมลมาตรฐาน | แปลงเป็นตัวพิมพ์เล็กทั้งหมด |
| Hostname | ตัวอักษร ตัวเลข ขีดกลาง จุด · ยาวไม่เกิน 63 ตัวต่อส่วน | แปลงเป็นตัวพิมพ์เล็ก |
| วันที่ | `YYYY-MM-DD` ใน API · `DD MMM YYYY` บนหน้าเว็บ | ⚠️ ห้ามใช้รูปแบบ `DD/MM/YYYY` ใน API เพราะสับสนกับ `MM/DD/YYYY` |
| จำนวนเงิน | ตัวเลขทศนิยม 2 ตำแหน่ง | ตัดเครื่องหมายจุลภาคออกก่อนบันทึก |
